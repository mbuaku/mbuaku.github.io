Case study 01

ElitesCloud: from one VM to a two-site HA Kubernetes platform

It started as a single Ubuntu VM and a fragile Vagrant setup. It's now a geographically split platform with an HA control plane, GitOps deployments, cross-site database replication and alerting that pages me. I treat it as production because it runs real workloads for real users.

Infrastructure as Code

  • Terraform provisions the libvirt/KVM VMs and networks. Ansible bootstraps the OS, kubeadm, containerd and the cluster.
  • The whole environment rebuilds with one command (./deploy.sh apply) in about 15–20 minutes.
  • Git is the single source of truth. No dashboard-only changes, so no drift.
  • Kubernetes v1.29 on containerd. About 192 GB RAM across two physical hosts.

Cross-site networking

  • Tailscale subnet routing joins the sites into one Layer 3 network (~15 ms).
  • Calico CNI with BGP and VXLAN for pod-to-pod traffic across sites.
  • Found and fixed a Tailscale/Calico SNAT conflict that broke pod routing. The fix is an iptables NAT exception that re-asserts itself automatically.
  • MetalLB and NGINX Ingress inside. Cloudflare Tunnel with active-active connectors outside.

CI/CD and GitOps

  • GitHub → Jenkins (build, test, SonarQube) → Docker Hub → ArgoCD (deploy).
  • Separation of duties: Jenkins never deploys, and ArgoCD is the only thing that changes the cluster.
  • 43+ ArgoCD applications across environments and namespaces.
  • Custom Jenkins agent images with Node.js, Docker Buildx and kubectl.

Data, backup and recovery

  • CloudNativePG with cross-site streaming replication. Moving off shared storage removed a single point of failure.
  • Runs PostgreSQL, MongoDB, Redis, Qdrant, MinIO and NFS.
  • Off-site backups: pg_dump, mongodump, etcd snapshots, Jenkins config and encrypted secrets.
  • Restore tests every month. PagerDuty alerts when a backup fails.

Observability

  • kube-prometheus-stack: Prometheus, Grafana, Alertmanager, node-exporter, kube-state-metrics.
  • Custom etcd alerting rules, with metrics scraped over mTLS.
  • PagerDuty escalation for production alerts.

Security and governance

  • Bitnami SealedSecrets, so encrypted secrets can live in Git.
  • Network policies, etcd mTLS and control-plane isolation.
  • Production-first policy: no placeholder credentials, no insecure dev shortcuts.
Reliability engineering

Incident reports

Real outages on this platform, each with a root cause and a permanent fix. I learn the most from these, and they're the part I most want to talk about in interviews.

INC-001

Master VM killed by host memory overcommit

Impact
The Linux OOM killer terminated the Kubernetes master VM, taking down the control plane.
Root cause
VM memory was overcommitted on the host, and nothing controlled where workloads landed.
Fix
Added host capacity, topology spread constraints, verified VM autostart, and automated health-check failover.
INC-002

Remote filesystem ownership corruption

Impact
A recursive ownership change ran against the wrong path on a remote host.
Root cause
An empty shell variable expanded inside a remote SSH command.
Fix
Wrote safety standards for destructive commands (set -u, guard checks) and moved critical remote work to idempotent Ansible.
INC-003

API VIP race condition after reboot

Impact
After a reboot, the Kubernetes API virtual IP never came up, so the cluster was unreachable.
Root cause
The VIP service started before the network bridge it depends on.
Fix
Added systemd dependency ordering, idempotent network setup, and checks that verify the node after boot.
